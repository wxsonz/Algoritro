# 6. Architecture

## 6.1 Ground rules

- **Static and dependency-free.** HTML, CSS and JS, with no build step and no `npm install`.
  JS uses **ES modules**, so it is served over HTTP (`npm run dev`, which runs the dependency-free
  `tools/serve.mjs`, or any static server; or published as a multi-file artifact). Node ≥ 18 imports the same modules for tests and
  offline Meta generation.
- **Data loading.** `core/data.js` reads `data/*.json` with `fetch()` in the browser and with
  `fs` in Node. Nothing imports JSON as a module: that needs import attributes, which older
  Node 18 releases and older browsers lack.
- **Deterministic.** The same input, hand and params always give the same stream.
- **Independent validation.** `core/replay.js` re-derives every state from the input and the
  op list, and shares no code with `core/machine.js`.
- **Light to draw.** Anything that moves on its own moves by `transform` or `opacity`, which
  the compositor animates without repainting, and card effects run only on the card in focus.
  Nothing animates a blur or an inherited custom property: a moving blur is redone every frame,
  and an inherited property restyles every element under it. The felt is painted once and
  overlays dim without a backdrop blur. During playback the board draws into an offscreen
  canvas (a font change on a canvas in the page forces a layout of the page), and keeps its
  sizes from `ResizeObserver` instead of reading them every move. On wide screens the board
  plate is a layout boundary (`contain: size layout style`), so a move lays out only the board.
  It sits in a plain block, `.boardslot`, because Chrome never lets a grid or flex item be a
  boundary: containment on a grid item does nothing. The played card takes its size from a measured row height, not from
  container units, which would restyle it with every move. The goal is 60 fps while playing,
  even without GPU compositing.

## 6.3 The Machine

Algorithms run on a `Machine`, which holds the ranked stacks:

- **ops:** `sa sb ss pa pb ra rb rr rra rrb rrr`, each applied and recorded. No-op
  suppression is a technique flag on the machine.
- **queries:** `a`, `b`, `size`, `indexOf(rank)`, `min/max`, `slotInA(x)`, `slotInB(x)`. They
  are read-only.
- **annotations:**
  - `m.phase(name)` starts a named phase.
  - `m.why(text)` sets the reason attached to the following ops.
  - `m.focus({ mover, target, range, set })` sets the ranks to highlight.
  - `m.overlay(kind, data)` attaches structured data for a view: `costs`, `chunks`, `lis`,
    `partition`, `bit`, `beam`.

## 6.4 Card modules

### Algorithm card

```js
export default {
  id: 'turk',
  kind: 'algorithm',
  family: 'insertion',
  name: 'Turk',
  tagline: 'Always make the cheapest move',
  rarity: 'common',
  claimedClass: 'O(n²)', proof: 'yes',     // 'yes' | 'avg' | 'no'
  grasp: 4, craft: 6, lines: 250,
  slots: 3,                                  // techniques added or swapped in
  natives: { pick: 'cheapest-pick' },        // locked, no slot
  open: ['anchor', 'cost', 'band', 'order'], // roles a technique may fill
  defaults: { anchor: 'keep-three', cost: 'four-way-cost' },  // replaceable, no slot
  finisher: 'hardcoded-three',               // default Finisher; 'open' = takes one, no default; null = none
  params: {},                                // e.g. { chunks: 11 } on Chunks; no slot
  maxN: 1000,
  run(m, hooks) { /* call hooks.anchor(m), hooks.cost(...), … where the role applies */ },
};
```

### Technique card

```js
export default {
  id: 'four-way-cost',
  kind: 'technique',
  role: 'cost',
  name: 'Four-Way Cost',
  grasp: +2, craft: +2,
  requires: ['pick'], conflicts: ['two-way-cost'],
  hook: { cost(fa, ba, fb, bb) { /* → { total, dirA, nA, dirB, nB } */ } },
};
```

A requirement on the card's own role names the host default it replaces, for example Second-Max
Lookahead: `requires: [{ role: 'retrieval', hostDefault: 'max-retrieval' }]`.

Post techniques implement `rewrite(ops) → ops`, and prep techniques implement
`prepare(input) → info`. `hand.js` resolves the slots, checks requires and conflicts, fills
empty roles with the card's defaults, and calls `run`. Natives and defaults use no slot. The
rules are in [04-compatibility.md](04-compatibility.md).

**Why hooks.** An algorithm exposes its decision points: which values to keep, how to price
a move, where to put a pushed value, how to retrieve. A technique replaces one decision. This
is what makes "same card, one technique toggled" an exact, fair comparison.

## 6.5 Card data

The card text (the idea, step by step, under the hood, lore, pros, cons) lives in one place: this spec. `tools/build-data.mjs`
extracts each card's section from `spec/cards/*.md` and `spec/techniques/*.md` into
`data/cards.json`, keyed by kind (algorithms, techniques, meta, cursed) because a leaf card can
share an id with its Algorithm card. The code keeps the name, tagline, scores and roles, and
`tests/data.test.mjs` checks that every card has its text and that the role table in
[04-compatibility.md](04-compatibility.md) matches the modules. `ui/markdown.js` renders
the subset the cards use (headings, lists, emphasis, code and tables), so the Codex still needs
no dependency.

## 6.6 The stack cache

Every result of one hand on one stack at one seed is kept (`core/stackcache.js`), so nothing is
measured twice (objective.md §10).

- **The precompute.** `tools/precompute.mjs` (`npm run precompute`, about 50 s on 30 cores) runs
  every legal hand (`core/combos.js`: each open role empty or filled, each Finisher; 563 hands) on
  every stack at the default seed, and writes `data/stacks.json` (about 1 MB). One worker job,
  `cells`, runs a hand once per seed and applies each of the 16 subsets of the post cards to its
  moves: they only rewrite the finished list, so one run serves all 16. A set of orders keeps only
  its worst order. `--check N` recomputes N random cells against the file.
- **The version.** The file carries a hash of the measuring code (`tools/version.mjs`: the engines,
  cards, stacks, jobs and DP tables). `tests/cache.test.mjs` fails when the code changes without a
  new precompute, and the browser keeps its own results under the same version, dropping others.
- **Lookups.** A hand finds its precomputed cell whatever the order of its slot cards, with its post
  cards in the cache's order; a hand with changed knobs, prep cards or another post order is
  measured on its own and kept as a single result.
- **The browser.** The Table loads the file and the IndexedDB records before its first stamps, and
  keeps every new result; ☢ fills the rest of a seed with the same `cells` job.
